## Base, selection and consequence

A source owns its existing logical base/occupied tile. Upper leaves, horns, limbs, shadows and profile bounds may overlap other tiles without adding occupancy or targets. One resource source per tile remains authoritative. Keep source appearance and the selected material's actual colour intact; warnings and selections are separate overlays, not whole-body recolouring.

For an already disclosed selected source, show a small base highlight only when the actual current command can act on that exact target. For a tree, use the existing suitable packed Axe and legal adjacent working position, label **Chop tree**, and place committed impact at the trunk. Deposits and small gathering sources keep their actual action names, tool rules, range and blocking/walkable behavior; no universal adjacent-harvest rule is invented.

Use `EarlyMaterialGameplayRules.quote(target:in:)` and the existing selected-tool/source action owners where applicable. Extract only permitted presentation fields; do not ship the raw Proposal or world/source graph to artwork. Other source types keep their real command owner. The ready result must include pending encounter/interaction priority, actual access and current campaign/version semantics. The new one-level access rule applies only when its version is implemented; artwork must not pre-apply it to old worlds.

If the base is disclosed but the current chosen action is unavailable, omit the ready highlight and show the existing truthful reason when selected: required tool, unsuitable tool, unavailable approach or the actual interaction-priority reason. Do not show a cost, count, quality or availability claim the owner has not provided. A stale/hidden target clears selection feedback; it is not retained as a marker into fog. Generic source presence and recipe relevance are not the same as action readiness; do not advertise the separately intended recipe-tracking presentation as part of this delivery.

Direction/selection uses the existing grid/command interface. No mesh hit test executes harvesting, extends reach or bypasses a pending encounter. Revalidate on command execution. Wrong/stale/cancelled/failed-save attempts produce no success impact, depletion or reward animation and retain existing no-spend behavior. A real committed hit uses its one existing turn/result; saved partial work remains. The last hit removes only that source's live crown/deposit and uses the actual committed cleared-base state. No second collection is generated by an animation or replay after reopen.
