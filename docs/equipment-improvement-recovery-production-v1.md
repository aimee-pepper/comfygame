# Equipment improvement and recovery — shared production contract

**6 September 2026 · Design-authored first pass under Aimee's whole-shop direction; implementation pending.** This closes ordinary services across the six completed maker packets. It is a content/rules contract, not an implementation receipt, new audit framework or extra phone-check assignment. Peerless has its accepted boundary below and remains unimplemented; its Mote-on-miss decision is still open.

## 1. Authority and the replacement

Read the current public Wiki's Crafting Overhaul and Design Decisions alongside this contract. Newer direct Aimee decisions override these starting choices. The six `*-whole-shop-production-v1.md` packets own their exact recipe, stat, tier and value tables; this contract supplies their shared service dispatch, ownership and migration rules. Their earlier references to a forthcoming equipment-service batch now refer here.

**New-policy gear improves through actual component replacement, the maker's supported remake/rebuild, and Weaponsmith's explicit fitting choice.** It does not inherit the old three-rank Reforge calculator, the historical proposed one-step +0.5 Reforge, tier-derived quality bonuses or paid material samples with no defined component. Ordinary refit is deterministic and costs 0 Essence. A new service adds no generic Power bonus.

**Legacy Reforge is deliberately retained for its supported older items.** It is compatibility behavior, not the destination for new-policy equipment. The later Peerless journey does not authorize converting old paid work, retiring a supported old action or charging again for it. This distinction replaces vague instructions to “preserve existing upgrading.”

Current source uses three legacy Reforge ranks, +0.2 continuous Power per rank. Successive costs are 2/3/4 qualifying samples at property 30/44/58 and 8/14/20 Essence. Slot properties remain Hardness for weapon/offhand/head/body, Flexibility for hands/feet, Density for tool and Lustre for keepsake. These are source facts, not a new delivery claim or recommended new progression. Fractional Power does not guarantee a changed rounded attack/protection at each purchase. Preserve the actual comparison; never advertise an invented +1. The unapproved August +0.5 proposal is historical only.

## 2. Which operation applies

| Pick, Axe or Scythe | Forge's named tool improvement table | Keep the one exact owned tool/progression; no generic refit, gear duplicate or new Recycler route |
| New Tannery garment refit | Built Tannery | Replace complete allowed parts; two Leather panels may be independent |
| Tannery variant change | Explicit Remake as the supported same-family variant | Complete destination recipe replaces complete old construction; same item and slot |
| New Bowyer weapon refit | Built Bowyer | Replace allowed parts, including independent throwing edges; same family/kind/Far reach; no ammunition inventory |
| New Weaponsmith weapon refit | Built Weaponsmith | Replace allowed parts; same family/kind/reach and selected fitting |
| Balanced ↔ Driving weapon fitting | Built Weaponsmith, same supported weapon | Free Home adjustment using unchanged parts; +1 Initiative or +0.75 Power as specified, recalculated once |
| Supported physical protection → Armoury profile | Built Armoury | Complete destination recipe for that same slot; 14 supported combinations, no Insulated shield |
| Armoury component refit | Built Armoury | Replace parts within the current Rigid/Balanced/Insulated profile |

Attendance and new tier fees do not gate the ordinary actions above beyond the explicit maker tables. Keep current Home/service access, learned families and target custody requirements. A polearm damage-kind change is a new craft, not a refit. A new craft creates a new owned item and never inherits the target's identity, inscription or permanent improvement. Armoury changes protection construction only; it does not create weapons, tools, keepsakes or Channelworks housings.

## 3. Eligibility comes from the item, not its name

Dispatch by versioned actual construction and service support before showing a price. A catalogue ID, tier, quality word, inferred species or identical-looking silhouette cannot prove a complete active component record.

1. **New complete receipt:** use its maker policy and the active components described here.
2. **Already-supported early complete receipt:** use its exact established early component owner. A supported deliberate refit/rebuild may write the new policy; opening a menu or loading a save may not. Preserve actual old lot prices and appearance. Recompute and preview the full destination before committing; new statistics may differ, and the player can cancel.
3. **Legacy, unknown or cumulative-only receipt:** keep the known old service route. No generic conversion, invented Hardwood, fake Leather measurements, fabricated missing bow points or full-recovery upgrade. An existing older recovery route remains bounded by its own policy; new returned parts must never be appended to its historical sample pool.
4. **Positive paid upgrade/legacy credit or another permanent effect:** admit to a modern mutation only when a version-specific adapter proves its exact contribution and preservation once. This batch supplies no new legacy-to-modern paid-credit adapter, so these targets retain their supported legacy route. Ineligibility is explained before consuming anything.
5. **Found, unique, Apex, narrative, inscription-specific or Channelworks gear:** retain actual existing protection and service rules. A found component description is not automatically a recipe or recovery entitlement. No new permission is inferred from visible anatomy.

Keep the worn/stored/Waiting location and actual owner for an in-place supported operation. Respect existing service locks and legal targets. Dismantling retains equipped/favorite/locked/protected-return/unique/Apex/narrative/legacy-credit restrictions. Display “This older piece needs its existing service” or the specific missing-record explanation instead of pretending the player lacks new ingredients.

## 4. One active construction; history is not inventory

The exact instance has one current active construction plus its chronological provenance. Each attached unit is allocated once to a current socket/bundle, retaining actual source portions, type, measurements, quality, full colour/Pattern and frozen nominal price. A unit cannot simultaneously be loose stock, attached to another item and available as an outgoing return.

A refit reserves the complete incoming bundle, releases only the replaced outgoing bundle, retains untouched parts, and computes the full new receipt. A remake/rebuild reserves the complete destination recipe and releases the complete old active construction. Preserve the same stable instance, allowed slot/kind/reach, owner, name/history and supported inscription. Never create a second base item. The recipe-specific calculator owns the resulting stats; do not add a newly calculated value to old Power/Protection.

**Explicit reuse is allowed.** The quote may allocate an outgoing component directly into the destination if it genuinely satisfies that slot. It is then retained/transferred, not both returned and consumed from phantom inventory. Example: move an existing Cord into the new binding, show it as reused, and charge only missing inputs. If reuse is not implemented, quote real available new inputs and return old parts honestly; do not silently require nonexistent duplicate stock after offering a reuse quote.

A no-change selection does nothing: no fee, history revision, grade roll, output or return. Each actual committed change leaves useful history, but every detached part is no longer recoverable from that item's history. Return, Storehouse and selectors may visually group equivalent parts under the accepted Hide/wood feedback rules; grouping never changes underlying ownership.

Recover prepared Cloth, Cord, Leather, Ingot, Haft and Collar as the selected prepared units. Do not also recover their Fibre, Hide, Salt, ore, Bone or casting fuel ancestors. Recover raw construction units and Resin only where the exact maker contract declares them recoverable. Bowyer's specified Clay return convention stays explicit. No new reverse-processing service. Tool improvements, foundations, consumables, processing fuel, Essence, Motes and consumed Reforge samples do not acquire recoverable gear components.

## 5. Permanent progress belongs to the exact item

Separate current component-derived stats, the chosen construction/profile/fitting, and any proven separately owned permanent effect. Recomputing material statistics must neither erase such an effect nor turn it into an endlessly repeatable bonus. An effect belongs to the same exact item and is applied through its actual rules owner once. It does not change source material quality, move into recovered stock, duplicate onto a new craft or count as a facility/recipe unlock.

Current `GearInstanceProfile.effectivePower` uses `legacyEffectivePowerCredit`, `reforgeRank × 0.2`, and its actual gameplay-fact offsets. `legacyPowerCredit` is a separate historical/display authority, not a second additive bonus. Preserve these existing owners; do not total both credit fields or re-run pre-migration catalogue-tier arithmetic after migration. Keep unique-rule growth separate where already supported.

Existing legacy Armoury explicitly resets Reforge/legacy credits as part of its separately disclosed confirmed legacy rebuild. That existing action is not an automatic migration or a model for new refits. Preserve its exact existing warning/choice, and never invoke it while claiming an ordinary new component replacement preserves paid work. No new silent reset or free refund is introduced here.

A future approved Peerless effect must survive supported same-instance refit/remake/rebuild, independently of the current material workmanship band. Replacing a component may change ordinary Power/Protection or workmanship; it must not silently lose a separately earned refinement. Its actual magnitude, eligibility and progression remain future service design, not an invented +1, +0.5 or next-tier credit in this batch. Old gold-name/found quality and the historical Peerless label cannot establish that a Mote was spent or a new refinement was earned.

## 6. Price and recovery cannot pay out twice

For new-policy ordinary gear, freeze **C = sum of the actual active recoverable components' nominal sale values**. Sale is C and buy is 2C. No extra quality, colour, species, fitting or profile multiplier. Refit/rebuild explicitly updates C from the committed destination; passive loads and registry edits do not reprice existing items. Existing old gear and old ingredient lots retain their known policy until an explicit supported operation.

Component returns carry their actual frozen values. Ingredient units with the same visible properties may have different historic prices; sum the actual allocated lots. Reforge costs and future refinement spending are not component value or recoverable currency. The future Peerless service must separately specify any trade policy before implementation; this packet adds no refinement resale premium.

New full recovery is not multiplied by the older Recycler 40/55/70% efficiency, nor supplemented by it or catalogue salvage. Those percentages remain only on their supported old sample-receipt route; fewer than two legacy samples recover none under that route, otherwise its existing capacity is retained. Ordinary catalogue salvage keeps its existing authored sequence. One item selects one recovery policy, exactly once.

Buying new gear for 2C then dismantling/selling gives C. Crafting from purchased components cannot yield more sale value than those components cost. Processing losses/fuel remain genuine, and refitting A→B→A merely moves actual parts. A failed save, duplicate request or reopening cannot repeat a return.

## 7. Peerless boundary and the one owner question

**Accepted:** a Mote plus a maximum-level shop plus its attending keeper gives a 100% outcome; one or two of those advantages still support a chance. A miss does not destroy or downgrade the item. The future journey must preserve the piece the player chose to improve.

**Still open for Aimee:** if an incomplete setup spends a Mote and misses, may it leave no lasting improvement, or must every spent Mote guarantee lasting progress? Design recommends lasting progress. Do not assume an answer, silently refund/spend the Mote, or reinstate the old twentieth-copy guarantee.

**Design work, not extra homework:** the eligibility band, statistical benefit, partial odds, ordinary attempt price/progress, exact maximum facility route and feedback remain a separate complete refinement contract after that experience choice. Forge T3 is its authored maximum, but built Tannery/Bowyer/Weaponsmith/Armoury ordinary access is not proof of a future maximum. Older internal tier counters or an attendance-derived effective tier cannot count the keeper twice. Do not sell an empty mastery tier or enable a paid attempt until its whole destination is defined.

All ordinary services in this packet are implementation-ready without that answer. Keep the unavailable future service honest; no active purchase button charging for undefined outcomes. Apothecary's supernatural bottles, Waystone's Mote and timed weapon coatings keep their separate owners. In particular, the accepted coating lasts on one weapon for one excursion across hits, encounters and reopening; a refit or new craft never creates or revives a coating.

## 8. Commit and focused cases

Use existing quote/transaction/save owners. Quote exact target identity, custody and revision; service/knowledge availability; active components and paid effects; incoming/reused/outgoing allocations; full before/after stats, workmanship, value and destinations. Stale owner, slot, construction, stock or service state invalidates the quote. Cancel/invalid selection/failed save preserves all state. Commit spend, exact same-item mutation or one-item destruction, returned goods and history atomically before success. Full Storehouse uses supported claimable Waiting custody; no loss, forced equip/packing, active-excursion snapshot mutation or fabricated success.

Use normal focused tests and the implementing lead's ordinary native route; Design does not repeat delivery checks. Concrete cases:

| --- | --- |

| Same visible Common old Leather valued4 versus a newly prepared historical cheap lot valued3 | Quote actual selected values; no reprice to today's table or invented uniform stock price |
| Recover Leather/Cloth/Collar with full parent history | Prepared unit only; no parallel Hide/Fibre/Bone/Iron/Salt/fuel return |
| Legacy ranks0/1/2/3 and both credit fields present | Preserve actual 0/.2/.4/.6 rank contribution and one effective credit; no +.5 migration, credit double count or new-policy eligibility by name |

| Supported refit retaining an independently owned permanent effect | The effect survives once through its actual owner; an unsupported legacy adapter refuses before spending |

| Stale quote, no-op, full storage, failed save, reopen/repeated action | Correct refusal/claimable custody and one durable outcome; no lost or duplicated item, source or return |

Engineering may implement in bounded commits within the existing whole-shop lane; this is not permission to supersede a current player blocker or dispatch isolated recipes. Exact fields/adapters are Engineering's choice within the existing gear/material owners. This packet does not request a new framework, configuration matrix or speculative Asset family.
