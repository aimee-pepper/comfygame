## Hold, slide, release to choose a tool

Recovered authority: `resource-world-first-pass-tuning-v1.md`, Harvesting controls and turn costs, settles **hold Interact for 0.40 seconds**, packed tools only, zero-turn selection, a persistent exact active-tool preference and separate harvest inputs. The cohesive plan and implementation roadmap agree on Interact/tool versus movement-centre/quick-item ownership. The earlier written sources do not explicitly specify the release gesture; Aimee now reaffirms holding continuously and sliding to the tool. Release-to-select closes that small interaction detail without a separate modal/tap sequence.

1. Begin pressing **Interact**. A release before the settled 0.40-second hold follows the existing ordinary Interact tap rules; do not introduce a new harvest action or turn cost.
2. At 0.40 seconds, open the field-tool choices while the same finger remains down. This recognizer now owns the gesture and suppresses an Interact tap on eventual release, including cancellation.
3. Slide that finger over an actually packed tool. Show its hover choice without committing a harvest or changing the saved tool on each crossed row.
4. Release over a valid packed tool to make that exact tool active and close the chooser. This costs zero turns, performs no movement, harvest, swing, gathering or automatic follow-on Interact action. No second tap is required.
5. Release outside a tool, lose/interruption-cancel the gesture, or invalidate the chosen tool while the menu is open: close and keep the previous valid selection. No turn, resource deduction or accidental tap. Returning toward the centre or empty area is a cancellation path, not an auto-selection of the first tool.

The chooser lists real tools in the dedicated tool roll, with their existing levels. It cannot select unowned/unpacked tools or grant a capability from town storage. Selecting a packed but unsuitable tool is allowed as a preference; a subsequent wrong-tool or insufficient-tier attempt refuses for zero turns and names the actual requirement. Do not silently choose a stronger or different tool for the player.

Keep the settled preference across excursions/relaunch, activating it only when that exact tool is packed. If not packed, clear active use and explain as already specified. Choosing a tool changes only that preference; it does not change harvested stock or advance world time. Actual work still uses a later Interact tap for eligible underfoot plants/loose material, or a later direction toward an adjacent blocking trunk/mineral node. Existing encounter/traveller/site/portal/hazard priority remains intact. No automatic harvest on menu release.

The movement-centre hold remains the separate quick-item surface. This request does not redesign or add automatic use to that menu. Keep the existing tool layout unless a small adjustment is necessary for continuous hit-testing; no radial-layout redesign is required. No new threshold or gesture tuning is requested from Aimee.

Engineering cases: 0.40-second continuous hold opens without release; slide across two choices commits only the released one; release outside/cancel/interrupt suppresses a tap; valid release does not swing or spend a turn; later ordinary input performs exactly its existing action; packed-only/stale-tool/insufficient-tier behavior stays honest. Use the actual installed target/default text; no configuration matrix or second Design phone verification.

## One tile, one resource placement

**Direct Aimee instruction:** “one tile, one node/resource.” Aimee subsequently clarified that the apparent stacking may be the accepted ability to mine an adjacent node. Actual duplicate occupancy is **unconfirmed** pending Engineering’s source-coordinate check. Adjacent mining remains valid and must not be removed or described as the bug. This invariant is settled without assuming that the reported image proves a violation.

Every generated tile may contain **at most one gatherable resource placement across all resource passes**. This is cross-resource occupancy, not one allowance per storage field, material family, generator pass or layer. It includes mineral nodes (Iron and all other mineral families, Coal, Quartz and similar), loose/gatherable deposits such as Clay and Salt, any gatherable Rubble, and harvestable flora including Logs-bearing trunks, Resin-bearing plants and Fibre/other harvestable plants. A trunk and mineral node on the same coordinate violate the rule even if code stores them separately or one is partly hidden.

One resource placement can supply its authored quantity and retain its multi-hit work/depletion state. Several units of Iron from one Iron node are not several placements. This does not authorize a second bonus source occupying that tile. A single canopy or decorative overhang may visually extend across nearby cells; its actual harvestable trunk/root placement still has one coordinate. An overhang never masks a second gatherable owner at that coordinate. Terrain, bed, liquid surface and decorative non-resource geometry are not themselves extra resource placements. Creature encounter rewards remain encounter rewards; do not recast their multiple loot units as static world nodes.

Apply the same occupancy claim to ordinary geology, later mineral passes, flora, named-resource guarantees, starter/recruitment source reservations, hand-gathered deposits and any supported underwater resource placement. At most one harvestable bed resource still occupies a wet tile; being submerged is not a second resource layer. Known/hidden status and depletion visuals do not allow concurrent extra placements.

A later pass must see earlier occupied/reserved coordinates. Resolve conflicts before finalizing placement, using another **legal, unoccupied, actually reachable** candidate under the existing host/tool/source requirements and deterministic generation rules. Do not silently overwrite a source, hide it under another, stack two yields behind one picture, count the same reservation twice, or weaken a written promise. If the full set of actual required reservations cannot fit, use the existing explicit generation failure/retry path; do not call an overlapping or missing guarantee valid. Optional placement may only be omitted under its existing quota policy, never used to silently discard mandatory source/quantity requirements.

None explicitly grants resource stacking. Their previously local/per-pass placement language now obeys this shared occupancy rule. Preserve water quotas, reachable interaction positions and existing habitat eligibility; this correction supplies no new quotas or landscape grading.
